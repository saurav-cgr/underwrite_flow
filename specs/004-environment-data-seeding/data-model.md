# Data Model: Environment Baseline and Evaluation Loading

No new database table or column is required. This feature maps new runtime and
load concepts onto existing persisted entities.

## Environment Mode

Runtime configuration describing one process.

| Field | Type | Rules |
| --- | --- | --- |
| `mode` | enum | `development`, `evaluation`, or `production` |
| `evaluation_loading_allowed` | Boolean | True outside production |

Validation rules:

- Missing mode defaults to development for the normal local setup.
- Unsupported values prevent process startup.
- Mode is fixed for the process lifetime.
- No secret or credential is included in status output.

## Common Baseline

The existing initialization result shared by all modes.

| Component | Existing persistence | Required state |
| --- | --- | --- |
| Schema | Alembic revisions | At current head |
| Demo identities | `users` | Three active fictional role accounts |
| Authorization | `roles`, `permissions`, mappings | Existing system catalogue |
| Products | Product and rulebook tables | Built-in versions imported |

The baseline contains no `Case`, `Submission`, `Document`, `Recommendation`,
or evaluation-result business row.

## Evaluation Dataset Version

Immutable identity computed from the existing corpus.

| Field | Source | Rules |
| --- | --- | --- |
| `dataset_sha256` | Exact dataset bytes | 64 lowercase hex characters |
| `expected_case_count` | Validated records | Current contract requires 90 |
| `source_case_ids` | Each record's `case_id` | Unique within the dataset |
| `synthetic_label` | Each fixture label | Exact label required |
| `configuration_manifest` | Product/version pairs | Every pair must exist |

## Loaded Evaluation Case

One source record mapped to existing business entities.

| Source value | Existing destination |
| --- | --- |
| Dataset hash + source case ID | `Case.idempotency_key` |
| Product code + configuration version | Pinned `ProductVersion` |
| Matching rulebook version | Pinned `RulebookVersion` |
| Journey type | `Case.journey_type` |
| Workflow payload | `Submission.payload.application` |
| Document identifiers | `Document.document_code` |
| Generated bytes | Upload volume plus `Document` metadata and hash |
| Derived workflow output | Existing workflow-owned rows |
| Synthetic source metadata | Append-only `AuditEvent.details` |

Validation rules:

- The idempotency key is namespaced by dataset hash and source case ID.
- Product, rulebook, and journey must match the exact source record.
- Application values must pass the pinned configuration's validation.
- Generated documents must pass normal upload validation.
- Expected route, missing-data, and conflict labels verify derived output only;
  they are not copied into the recommendation.
- A mismatch on an existing reserved identity is a collision and is never
  overwritten.

## Evaluation Load Marker

Existing immutable audit events represent progress and completion.

### Per-case event

`event_type = evaluation_record_loaded`

Safe details:

- `dataset_sha256`
- `source_case_id`
- `split`
- `fixture_label`
- pinned product and rulebook version identities

### Dataset completion event

`event_type = evaluation_dataset_loaded`

Safe details:

- `dataset_sha256`
- `environment_mode`
- `expected_case_count`
- `verified_case_count`

No credential, document text, application payload, token, or hidden workflow
state is stored in either marker.

## State Transitions

```text
preflight
  ├── forbidden production ──> rejected, zero writes
  ├── invalid corpus/baseline ──> failed, zero writes
  └── valid ──> loading
                 ├── exact existing record ──> verified
                 ├── missing stage ──> resume ──> verified
                 ├── collision/failure ──> incomplete, retryable
                 └── all records verified ──> complete audit marker
```

The command reports completion only after verifying all expected cases. Partial
records remain safely identifiable and are resumed on the next invocation.
