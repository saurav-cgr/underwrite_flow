# Documentation Model: README Project Tour

## Project Tour

| Field | Meaning | Validation |
| --- | --- | --- |
| location | Opening README section after purpose | Appears before setup |
| contents | Links to major README headings | Every target exists |
| purpose | Fictional triage demonstration summary | No final-decision claim |

## Capability Summary

| Field | Meaning | Validation |
| --- | --- | --- |
| capability | Existing product area | Matches an implemented feature |
| behavior | Plain-language demonstrated outcome | Concise and factual |
| boundary | Relevant safety constraint | Preserves human authority |

## Case Lifecycle

| Stage | Reader-facing meaning | Required boundary |
| --- | --- | --- |
| intake | Applicant submits fictional evidence | Evidence is untrusted |
| configuration | Selected journey and version apply | Case remains pinned |
| reconciliation | Evidence is checked | Rules outrank model input |
| recommendation | One queue route is suggested | Not an insurance decision |
| confirmation | Underwriter confirms or overrides | Required before close |
| audit | History records the process | Immutable business history |

## Component Responsibility Summary

| Area | Reader-facing responsibility | Boundary |
| --- | --- | --- |
| interface | Role-based presentation and interaction | No underwriting truth |
| workflow | Intake, evidence, reconciliation, routing | No finalization |
| storage | Cases, versions, audit, and checkpoints | Local source of truth |
| provider | Optional redacted assistance | Not an authority |
| evaluation | Isolated synthetic verification | No shared development state |
