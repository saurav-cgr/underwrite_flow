# README Project Tour Contract

## Required order

1. Existing product purpose and non-decision boundary
2. Linked table of contents
3. What this demonstrates
4. Capability summary
5. Existing quickstart, role verification, and automated checks
6. Existing architecture diagram with lifecycle and responsibility summary
7. Existing safety, environment, troubleshooting, limits, and deeper links

## Content contract

| Element | Required content |
| --- | --- |
| Contents | Links for tour, setup, checks, architecture, eval, and limits |
| Overview | Fictional, human-governed triage demonstration |
| Capabilities | Journeys, versions, reconciliation, review, audit, evaluation |
| Lifecycle | Intake to underwriter-confirmed route |
| Responsibilities | Interface, workflow, storage, provider, evaluation |
| Boundaries | Synthetic data only; no insurance approval or final automation |

## Safety wording contract

The project tour MUST state or link to all of these existing facts:

- An authenticated underwriter confirms or overrides every final route.
- The system recommends expedited, standard, or specialist review only.
- The system does not approve, decline, bind, price, issue, renew, or cancel.
- Only fictional data belongs in the local demonstration.
- Uploaded evidence is untrusted and deterministic rules outrank model input.
- Product versions remain pinned to cases; audit history is immutable.
- Evaluation is isolated and synthetic; production mode is not a readiness or
  compliance claim.
